# 知卷 · 产品说明与开发文档 v1.2

DeepSeek 官方 API + Hermes；不引入 LangChain、LangGraph；覆盖小学、初中、高中；第一版不接题库。

# 第一部分｜产品需求说明

## 01 产品定位与已确认边界

**产品名称：知卷 · Hermes AI 原创命题工作台。文档版本：1.2，编制与资料核查日期：2026-09-15。**

目标用户是需要编制练习与试卷的教师、教研人员及机构管理员。产品根据用户确认的学段、学科、教学范围与试卷要求，由 Hermes 直接调用 DeepSeek 原创生成题目，执行独立解题与专用检查，允许教师修改、复核，并从同一版本导出学生卷、答案解析和评分细则。

本版固定三个边界：覆盖小学、初中、高中；不建设、不接入题库；题目由 Hermes 现场组织生成。历史试卷只用于恢复、编辑和审计，不参与下一次题目检索、推荐、抽取或模型长期记忆。课程配置、学科规则与软件测试样例不是生产题库。

本文的接口、目录、数据库、Skills、阈值和技术架构均为本项目的建议设计，不能理解为 Hermes 已经内置的功能。已核查的第三方能力以文末 [Sxx] 标记注明；所有性能与质量目标均是待验证的验收建议，不是已测成绩。附件提供开发契约和可测试参考代码，不是已经完成的全栈应用。

### 1.1 目标与非目标

| 类别 | 第一版决定 | 不应误解为 |
| --- | --- | --- |
| 原创生成 | 新题由模型按蓝图生成，保留生成来源与版本 | 保证全网从未出现相似题 |
| 全学段 | 产品结构和发布验收同时覆盖小学、初中、高中 | 仅有年级选项就算覆盖完成 |
| 自主工作 | 自动规划、生成、检查、有限修订 | Agent 可以自行改规则或直接批准正式发布 |
| 无题库 | 无题库导入、向量检索、抽题、题库运营 | 不保存草稿、成果和审核记录 |
| 可追溯 | 保存题面版本、证据、审批和导出文件 | 同一随机种子必然重现模型输出 |
| 内容正确性 | 通过规则、工具、独立审题和人工审批建立证据 | 所有学科能够获得自动化数学证明 |

第一版不包含学生账号、在线考试、自动批改、成绩排名、支付、学校题库、公开题目市场、OCR 识别整本教材、模型训练与微调。A/B 卷的严格等值评估也不属于第一版；可另建两个生成任务，但不得承诺等值。

### 1.2 设计假设

默认以中文界面、教师桌面浏览器使用为主，移动端用于查看和轻量修改。课程体系默认提供中国大陆配置，但保留地区与学制字段；小学年级和初中年级不得写死为唯一学制。高中使用学年标签及必修、选择性必修、选修等模块信息。模型服务已确定为 DeepSeek 官方 API，Hermes 为唯一 Agent 执行框架。学校、地区、具体模型 ID 和部署环境仍需在上线前确认；它们不是要求重新选择其他 Agent 框架。

默认部署为一个组织可独立使用、底层支持组织隔离的 Web 应用。首发可只启用一个组织；多组织隔离从数据设计开始存在，避免后续改造泄露试卷。第一版不要求 GPU，模型通过经批准的服务端 API 调用；本地推理是后续部署选项。

## 02 用户角色与权限

| 角色 | 允许的操作 | 明确禁止 |
| --- | --- | --- |
| 命题教师 | 创建配置、确认蓝图、生成、编辑、查看本组织授权试卷、提交复核 | 修改校验记录、绕过发布策略 |
| 审核教师 | 盲审题面、查看证据、提出问题、批准指定版本 | 批准已经变更的旧版本；在要求分离时审核自己命制的试卷 |
| 组织管理员 | 管理成员、课程配置、审核策略、预算和保留期限 | 默认不因“管理员”身份而获得全部答案读取权 |
| 运维人员 | 查看脱敏日志、运行状态、备份与恢复 | 默认读取试题正文、模型密钥或学生数据 |
| Agent 服务身份 | 获取单次任务允许的数据、提交候选题、请求工具检查 | 直接访问业务数据库、跨任务搜索、发布、改权限、改生产 Skills |

身份权限由后端和工具网关校验。提示词中的“只访问本组织”不构成安全机制。个人练习模式可由同一教师完成命题与最终确认；学校正式考试模式使用独立审核人策略，不得以个人练习模式绕过适用要求。

## 03 学段、学科与题型覆盖

### 3.1 全学段配置模型

配置链为：课程体系／地区 → 学制与学段 → 年级 → 学科 → 教材版本／模块 → 已教知识点 → 考查能力与允许方法。教材信息是辅助元数据，不是可靠课程映射的替代物。教师必须确认本次范围；仅填“七年级数学”不能直接进入严格教学适配模式。

| 学段 | 建议提供的学科配置组 | 需要特别约束的内容 |
| --- | --- | --- |
| 小学 | 语文、数学、英语、科学、道德与法治等，由组织配置实际开设情况 | 字词与阅读负担、数值范围、生活经验、允许方法、答题空间 |
| 初中 | 语文、数学、英语、物理、化学、生物、历史、地理、道德与法治等 | 先修知识、概念边界、实验条件、逻辑链、学科术语 |
| 高中 | 语文、数学、外语、物理、化学、生物、思想政治、历史、地理等 | 模块范围、综合推理、参数边界、论证、开放题评分 |

以上为建议的产品配置组，不是全国统一开课年级表。不允许自动推定每个地区同一年级都开设相同学科。音乐、美术、体育、信息科技等可复用平台，但其听觉、实作或编程等能力必须单独验收，不因“自定义学科”输入框而自动宣称支持。

### 3.2 题型契约

第一版内建单选、多选、判断、填空、计算／解答、简答、阅读／材料综合题、论述／作文。材料题以共享材料加子题表示；分值累加只统计叶子题，不能再次计入父题分值。客观题按稳定选项 ID 存答案，A/B/C/D 只是显示标签。

图表题采用受控结构化图形描述生成 SVG 或静态图，图片属于试题内容的一部分。无法生成可靠图示时，报告不支持或待复核，不能生成“如图”但不附图。第一版不接自由绘图模型，不把漂亮图片当成精确几何图。听力、视频和实际操作任务可形成文字草稿，但不标记为可完整交付的对应题型。

### 3.3 能力登记与上线定义

每个“学段 × 学科 × 题型”组合登记 generation、verification、rendering 三项状态，各取 READY、REVIEW_REQUIRED、UNSUPPORTED。READY 表示已通过指定测试范围，不表示百分之百正确。缺少专用自动检查的开放题，可以在有明确人工审核规程时达到产品可用；不能伪装成自动证明。

小学、初中、高中必须同时进入端到端验收。整个产品标记“全学段正式上线”前，首发承诺清单内的所有组合都必须具备生成、编辑、导出与对应复核流程。研发可按基础设施和功能层递进，不能以“以后再支持高中”替代本版范围。

## 04 输入字段与交互规则

### 4.1 必填、可默认与可选信息

| 字段 | 要求与示例 | 校验规则 |
| --- | --- | --- |
| title | 试卷名称，1–120 字 | 去除控制字符，不作为文件系统路径 |
| curriculum_system / region | 课程体系、地区 | 不根据 IP 推定课程体系 |
| stage / grade_label | primary、junior、senior；如“七年级” | 与学制配置匹配；自定义值需教师确认 |
| subject | 本次学科 | 必须命中已登记配置或显式进入待配置状态 |
| textbook / module | 教材版本、册次或模块，可留空 | 无证据时标为用户自报，不宣称已核对 |
| taught_scope | 已教范围、知识点及禁止内容 | 非空；标记教师已确认及确认时间 |
| purpose / usage_context | 练习、诊断、复习、正式测评；个人／学校日常考试等 | 触发适用策略，不能仅靠标题判断 |
| total_score_x100 | 总分乘以 100 的整数 | 如 100 分存 10000；不使用二进制浮点求和 |
| sections | 题型、数量、每题分值、知识点要求 | 分数、题型和题数互相一致；矛盾时不消耗模型预算 |
| duration_minutes | 预计作答时长，可不填 | 有限正整数；标记预估而非实测 |
| difficulty_distribution | 按分值分配的难度倾向 | 总权重为 100%；只标为预估 |
| provided_materials | 可选的教师粘贴原文、来源说明与使用权确认 | 只用于本次任务；不收集或检索历史材料 |
| cognitive_targets | 理解、应用、推理、表达等 | 选择项加自由说明，不硬编码为普适标准 |
| permitted_methods | 可用方法、工具、计算器、材料 | 用于适配检查，不直接证明题面正确 |
| output_preferences | 纸型、字号、答题空间、学生／教师版 | 对正文保持同源；版式不改变题义 |

使用简单模式时，教师可只输入范围并选择预置卷面规格；所有默认字段在生成前集中展示。高级模式允许按题指定目标。没有学生个人数据也能生成试卷，默认不收集学生姓名和学习档案。

### 4.2 分配规则

知识点和难度默认按分值计，不按题数计。一题跨多个知识点时，使用分值归属权重，合计等于该题分值；同一分数不能重复归入多个知识点。整数分配不能精确实现目标百分比时，显示实际分配与偏差，由教师确认，禁止暗中调整。

预计用时由题目估计值合计，并显示“未经过学生实测”。难度使用“教师目标／模型预估／人工确认”三个独立字段；本版不构造虚假的实测得分率。

### 4.3 非正常输入

总分不匹配返回具体差额；课程范围不足则停留在配置状态；要求不存在的图片或听力素材时指出缺失；用户同时要求“仅已教内容”和“超出范围的竞赛方法”时显示冲突。敏感内容、真实个人信息和提示注入文本作为不可信输入处理，不扩大 Agent 权限。

## 05 核心流程与页面说明

### 5.1 配置与命题蓝图

教师创建草稿后先请求规划任务。规划器只输出题目槽位，不生成最终题干。每个槽位包含题型、分值、知识点、能力目标、预估难度、材料依赖和评分结构。后端检查槽位总分与配置一致，再交给教师确认。

教师可以调整某个槽位，但不能在未重新确认蓝图时启动整卷生成。配置或蓝图变化形成新 revision，历史确认自动失效。预设配置可启用“自动确认明确蓝图”，但首次使用和存在任何配置偏差时仍需确认。

### 5.2 生成与检查过程

进度页显示已提交槽位数、当前生成数、已完成检查数、待修订数、待人工复核数和累计成本，不用虚构的线性百分比。只有后端收到真实事件后才更新状态。用户可离开页面后回来查看，也可取消任务；取消不意味着供应商已经停止计费，界面说明可能仍有在途调用费用。

按材料组或独立题执行生成。阅读材料先冻结，子题共享同一材料版本；修订材料会使全部关联子题校验失效。每道题先做结构检查，再盲解和学科检查，最后形成问题列表。自动修订只针对问题和允许改动的字段，不能改写蓝图来凑数。

### 5.3 编辑工作台

左侧显示题目目录和状态，中间编辑最终题面，右侧显示答案、评分点、独立解答和检查依据。可切换真正的学生预览：后端返回的数据中不包含答案，而不是仅用 CSS 隐藏。公式使用专用节点或文本加 LaTeX 字段，不允许原始 HTML 直接执行。

“重新生成此题”沿用槽位要求，创建新题目版本，旧版本保留，不从历史记录抽题。新版本必须重新盲解。编辑保存使用 If-Match 乐观锁；发生冲突时并排比较，不以最后一次写入覆盖他人内容。第一版不做实时多人协同编辑。

### 5.4 审核与发布

审核页先展示未解决问题。硬错误不能被教师一键忽略；应修改或删除相关题目并更新蓝图。对工具能力未覆盖的 REVIEW 项，授权审核人可通过明确人工裁决关闭，记录依据、人员和当前内容指纹，但不把原始自动结果改成 PASS。

正式发布前必须完成内容审核和最终文件预检。学生卷、教师卷、评分细则来自同一冻结快照；先生成权限受限的待审最终文件，审核预览层显示“待审核”（不改文件字节）；检查后批准 render_hash，再发布这些文件本身。可下载的带水印草稿是独立产物，不能复用其审批发布无水印文件。

### 5.5 历史与管理

历史页面管理试卷项目、版本和导出，不提供跨试卷题目检索或抽取。管理员页面管理模型路由、预算、学科能力、审核人数、Skills 版本与数据保留。模型密钥只在服务端保存，前端最多看到密钥别名和最后轮换时间。

## 07 内容质量与使用边界

“正确”拆为五类证据：结构与分值、答案与评分、语义与条件、教学适配、最终排版。任何一类没有证据，都不能以另一个维度的高分代替。数学表达式通过不代表自然语言题面没有错；两次模型答案一致也不等于正确性证明。

本版不引入外部事实库，也默认关闭网页搜索。语文／英语阅读可生成原创短文，但要标识为 AI 创作，不得伪称某作家作品；古诗文、历史引文和精确事实应由教师提供原文或人工核实。历史、地理、政治等依赖外部事实的题，没有证据时标记事实待核，不得由模型自造出处。时间敏感内容需要明确基准日期及审核，否则不进入已核实状态。

对于学校日常考试使用，中国大陆相关通知要求命题与审核人员分离，原则上审核把关人员不少于 3 人；小学一二年级不进行纸笔考试。[S21] 因此产品保留全学段练习能力，但学校日常考试模式在适用配置下阻止相应低年级纸笔考试，并启用独立多审核人策略。这不是禁止所有低年级学习练习，也不能用更改标题规避实际用途。

对公众提供生成式 AI 服务、个人信息处理和生成内容标识的适用义务，需要根据实际运营模式进行上线前法律审查；不能因只服务教师而直接假定全部豁免。[S22][S23] 本文提供技术控制设计，不作合规通过或法律意见的保证。

# 第二部分｜技术选型与架构设计

## 08 技术选型结论

建议采用“模块化业务后端 + 持久任务队列 + 隔离 Agent 执行器 + 独立校验与排版服务”。业务代码先保持一个仓库，运行时按权限与资源隔离为不同进程，不在第一版引入复杂微服务治理。Hermes 是受控的任务执行组件，不是业务数据库、发布审批系统或安全边界。

### 8.1 推荐技术栈

| 层 | 推荐选型 | 选择理由与落地约束 |
| --- | --- | --- |
| 前端 | React 19.x + TypeScript + Vite | 适合交互式编辑工作台；无需首屏搜索引擎优化，不增加 SSR 服务。React 与 Vite 能力依据官方文档。[S08][S09] |
| 前端运行环境 | Node.js 24 LTS；依赖 lockfile | 核查时 24 分支为 LTS。[S10] 不把 latest 标签作为生产版本 |
| UI 与编辑 | CSS 变量 + 组件化表单；结构化内容块编辑器 | 第一版不引入任意 HTML 编辑；公式、选项、材料、评分点有独立字段 |
| 业务 API | Python 3.12 + FastAPI + Pydantic 2 | 和 Hermes／数学工具共享语言；严格校验请求、响应和模型输出。[S11][S15] |
| 模型服务 | DeepSeek 官方 API | 由 Hermes 原生 provider 直连；五角色默认同模型、隔离运行，不要求第二供应商。[S27] |
| Agent 集成 | Hermes 固定提交 + 薄 Python Adapter | 唯一 Agent 执行框架，直连 DeepSeek；Adapter 只接入与约束运行，不再套框架。[S02][S06][S27] |
| 长任务 | Celery 5.6 系列 + RabbitMQ | 负责投递、进程故障恢复与执行资源分配；不负责 Agent 决策或内容修订循环。业务状态落 PostgreSQL。[S12][S13] |
| 数据库 | PostgreSQL 18.x + SQLAlchemy 2 + Alembic | 事务、版本、审计与组织隔离；RLS 是补充防线而非替代业务鉴权。[S14][S16] |
| 实时进度 | REST 命令 + SSE 事件流 | 单向状态推送足够；事件从持久表重放，前端断线不影响任务 |
| 文件存储 | 开发用本地适配器；生产用私有 S3 兼容对象存储 | 存放素材、审核文件与发布产物；私有桶、签名访问、按组织授权 |
| 校验 | 确定性 Python 规则 + 受限数学 AST + SymPy | 数学工具只处理支持范围；不直接执行模型代码或不可信表达式。[S17] |
| 排版 | 同源 HTML 模板 + KaTeX + Playwright Chromium | 主格式 PDF；字体和素材自托管，固定渲染镜像。[S18][S19] |
| Word 导出 | python-docx + 受控公式转换／图形回退 | 独立导出管线，不承诺与浏览器分页完全一致；公式回退为图时需明确 |
| 部署 | Linux 容器，开发 Compose，生产受控容器运行环境 | Agent、验证器和渲染器隔离；第一版不强制 Kubernetes |
| 可观测性 | 结构化日志 + OpenTelemetry + 指标仪表盘 | 串联 API、任务、模型和工具调用；默认不记录题目正文。[S20] |

除表中明确版本系列外，其余依赖在集成测试通过后写入精确锁文件；开发负责人需保存版本清单与软件物料清单。建议版本不是已验证的整套兼容性结论。Hermes 当前 pyproject 声明 Python >=3.11,<3.14，本文选择 3.12 位于该范围内，但仍需在固定提交上做安装与冒烟测试。[S06]

### 8.2 为什么不选另一套架构

不使用 Next.js 作为必需层，因为教师工作台不依赖 SEO，重复增加 Node 服务端没有明确收益；已有 Next.js 团队可使用，但命题仍由后端队列执行。本项目使用 Hermes 作为唯一 AI 任务执行与工具调用框架，直接接入 DeepSeek API，不引入 LangChain、LangGraph。此处是项目选型决定，不是声称 Hermes 需要这两个框架；核查时官方依赖清单未将它们声明为直接依赖。[S06][S27]第一版不建向量数据库、不装题库搜索服务，也不因为“AI 项目”默认引入 GPU。

不把生成过程放在 FastAPI 请求线程或简单 BackgroundTasks 中；官方文档对较重、跨进程的任务建议考虑 Celery 等队列工具。[S11] 不只靠 Redis Pub/Sub 保存进度；本方案默认不依赖 Redis，RabbitMQ 管投递，PostgreSQL 管持久事实，SSE 管用户观察。

Temporal 等持久工作流可在长周期复杂流程增多后评估，目前使用明确的数据库状态机、事务 outbox 和幂等阶段任务即可。不允许因为未来可能接题库而提前建设题库服务。

### 8.3 DeepSeek 直连与角色配置

第一版直接使用 DeepSeek 官方 API，不部署本地模型，不要求第二家模型服务。planner、author、solver、reviewer、exam_reviewer 是五个逻辑角色，默认使用同一经过验收的 DeepSeek model_id，但各次运行使用独立上下文和最小权限。独立解题报告必须标记 SAME_MODEL；同模型的两次一致作答不能宣称异构验证，更不能代替工具证据和教师审核。

DeepSeek 已是本版选定服务，不再是待选供应商。Hermes 原生 provider 配置使用 deepseek，密钥变量为 DEEPSEEK_API_KEY。[S27] 工具调用和 JSON 输出需分别验收；JSON 合法不等于学科正确，空输出及非法字段必须拦截。[S24][S25] 具体 model_id 保留明确占位符，待账户可用性、工具调用和三学段实测后冻结；不填写未经验证的型号、价格或性能。

建议盲测权重：严重错误漏放控制 35%，教学与语言适配 20%，题型与评分完整性 15%，工具／结构契约通过率 15%，每道可用题成本 10%，延迟 5%。这是选择规则而非测试结果。各学段分别统计，不可用总体均值掩盖高中或开放题失败。

### 8.4 单一 Agent 框架与职责归属

核心路线固定为“DeepSeek + Hermes + 自有 Skills + 受控检查工具”。不安装 LangChain、LangGraph，不另建图工作流来包裹 Hermes。以下是本项目的职责约定，不是声称这些边界由工具自动提供。

| 能力 | 唯一负责者 | 明确不做什么 |
| --- | --- | --- |
| 生成、工具调用与题目修订 | Hermes，调用 DeepSeek | 不直接审批、发布或改生产规则 |
| 网络请求重试 | 经审定的 Hermes 请求层 | 不让 SDK、Adapter、Celery 各重复重试 |
| 投递与进程故障恢复 | Celery + RabbitMQ | 不因答案错误重新生成整套试卷 |
| 状态、预算、版本与审批 | 业务后端 + PostgreSQL | 不实现第二套模型工具调用循环 |
| 输入输出映射、运行启动 | 薄 Hermes Adapter | 不承载额外 Agent 框架 |
| 工具授权与盲解隔离 | 业务工具网关 + 受控运行环境 | 不只依赖提示词或新建子代理 |
| 数值与结构检查 | 专用检查器 | 不把同模型一致回答当正确性证明 |
| 排版与 PDF 导出 | HTML/CSS + KaTeX + Playwright | 不参与命题决策或答案判断 |

同一道题只有一个由后端记账的 repair_attempt；Hermes 修订请求必须先获得对应额度和最新版本授权。队列重投只能恢复同一阶段，不能再增加一条隐形修订循环。首版同模型模式关闭未经批准的备用供应商和辅助模型路由；不支持的图像理解转待复核，不暗中切换模型。

## 09 系统边界与运行结构

```text
浏览器工作台
  → 业务 API：鉴权、配置、版本、审批、预算
      → PostgreSQL：任务与领域状态、事件、证据、outbox
      → RabbitMQ：只投递任务标识与阶段信息
          → Agent Worker → 薄 Hermes Adapter → Hermes Agent → DeepSeek API
          → Validator Worker → 专用检查器
          → Renderer Worker → HTML / PDF / DOCX
      → 私有对象存储：素材、快照、发布产物
  ← SSE：真实任务状态、检查摘要、成本与错误
```

业务后端持有任务状态、阶段准入、修订预算和发布条件；Hermes 是唯一 Agent 循环，在批准范围内命题、调用工具、提出并执行修订。Celery 只负责执行和投递恢复，不再为内容错误额外套一层自动重做循环。工具结果必须通过受信服务写入证据表；模型写出的“检查通过”只是建议文本，不赋予校验权限。未经审批的候选题可以保存，最终文件也可在受限审核区预生成，但不得公开下载或标记正式发布。

### 9.1 组件职责

API 不运行长时间模型循环。Agent Worker 从任务服务获得当前阶段的最小输入，不读取数据库全表。Validator Worker 仅获得题面、参考解答或所需计算数据，其返回由服务端身份签名和存储。Renderer 仅加载被批准的文件及字体，网络默认关闭。对象存储密钥不传给 Agent，由资源代理颁发短时、限对象访问权。

开发环境可用一个宿主机运行多个容器，生产可拆为不同节点。宿主机启动 Agent 沙箱的能力只属于受控调度器；绝不把 Docker socket 挂入可被模型执行代码的容器。没有配置强隔离时，禁用任意 terminal／execute_code，只开放受控业务工具。

## 10 Hermes 集成规范

### 10.1 固定版本与 Adapter

官方架构将 AIAgent 作为核心，提供集成入口和自身的工具调用循环。[S02] 本项目 Adapter 只是普通 Python 接入层，负责参数转换、版本校验、启动受控运行和结果映射；不是第二套 Agent 框架，不依赖 LangChain 或 LangGraph。run_stage、cancel、health、capabilities 为自有契约，真实 Hermes 参数、事件和取消行为需在固定提交上验证。

附件 reference_code/adapter_contract.py 是自有接口契约，不含未验证的 Hermes 调用伪实现。完成适配后需通过五项集成冒烟：成功返回结构化候选题、工具执行事件、结构无效时拦截、超时与取消、隔离任务不能读取其他任务内容。

每个运行实例使用新的任务目录和 HERMES_HOME，挂载已审定只读 Skills。默认不加载用户历史、长期记忆、跨会话搜索、社区 Skills 自动安装或外部消息渠道。不要仅删除最终对话，仍留下共享缓存、索引或工具日志中的答案。

### 10.2 盲解不是普通 /review

官方子代理默认继承启用工具集并共享父任务工作目录；/review 还会读取近期对话。[S04] 因此本系统不以 /review 代替盲解，也不把 git worktree 当作答案保密隔离。盲解由独立运行实例执行，输入仅包括最终题面、选项、必要材料、已声明可用方法和资产。

盲解运行实例没有答案 API、作者工作目录、试卷管理数据库、共享对话历史或可搜索的运行日志。内部 grant 绑定 tenant_id、job_id、question_revision_id、stage、allowed_tools、expires_at，且服务端以可信任务生成这些字段，不能信任 Agent 自报的组织编号。

作者参考答案和解析在盲解完成后才交给比较器。盲解应给出简洁可审核解答、结果与未确定条件，不要求存储或展示模型私有思维链。用户界面展示工具动作、可验证计算和审题结论。

### 10.3 允许的工具

| 工具 | 调用者 | 服务端验证 | 结果 |
| --- | --- | --- | --- |
| get_generation_brief | planner／author | 限当前阶段与任务 | 冻结配置、槽位与规则版本 |
| validate_structure | author／reviewer | 输入大小、Schema 版本 | 结构问题清单 |
| solve_independently | 受控流程服务 | 当前题面版本、盲解权限 | 独立运行引用，不直接暴露作者答案 |
| verify_math_ast | solver／reviewer | AST 白名单、资源限制 | 支持范围、计算证据、PASS／FAIL／REVIEW |
| render_diagram_spec | author | 受控图形 Schema | 图形资产、结构校验与内容哈希 |
| submit_candidate | author | 当前槽位、版本、预算、工具授权 | 候选版本 ID，不是发布 |
| submit_audit_summary | reviewer | 关联可信检查记录 | 模型审查意见，不覆盖工具证据 |

第一版优先通过窄的自有工具适配器开放这些接口。需要跨语言工具时可通过 MCP 接入；Hermes 官方支持 MCP，但 MCP 协议本身并不代替业务权限、输入校验和结果可信度判断。[S26]

### 10.4 限制与异常策略

建议初始策略：每题初次生成加最多两轮修订；每角色单次最多 12 个工具循环；每题模型请求上限 12 次；整卷请求上限由题量与预算计算；外部请求设独立超时。所有值属于本系统 policy，不应原样塞进 Hermes config.yaml。配置必须校验并落入任务快照。

当前源码可见 max_iterations 存在极大的默认值，不能沿用为生产成本控制。[S07] 应同时设置内部迭代上限和外部的调用额度、费用预算、截止时间、进程 CPU／内存／网络限制；任何一层失败都不能继续无限修订。

DeepSeek 429／临时网络错误只由已审定的 Hermes 请求层进行有限退避；SDK 的自动重试必须纳入同一额度，不能与 Celery 叠乘。题义错误由 Hermes 按审核反馈执行有限修订；预算及修订次数由业务后端原子计数。拒绝、超预算和参数冲突不自动重试。计费未知记录 usage_unknown。第一版禁用自动跨供应商 fallback；管理员变更 model_id 必须创建新 attempt 并重新检查。

### 10.5 Skills 管理

五个核心 Skill 为 exam-planner、question-author、blind-solver、question-reviewer、exam-reviewer。每个 SKILL.md 只放稳定流程、输入输出约定和失败规则；年级、学科、教材与本次要求在结构化上下文中传入。学段与学科规则包独立版本化，避免复制 12 套几乎相同的流程。

Hermes 支持 Skills，且存在技能写入审批机制。[S03] 生产仍应挂载只读 Skills，并移除写工具；skills.write_approval: true 只是附加措施，不能阻止拥有宿主机写权限的其他工具绕过。Agent 可输出“规则改进建议”，由维护者运行回归、审查 diff、签发新 bundle，再灰度启用。

每个 bundle 记录版本、内容哈希、适用能力、测试报告和批准人。生产不从 Skills Hub 自动安装新技能，不允许技能声明随意扩大凭据传入范围。[S05] 任务开始后规则不可变更；需用新版本时创建新任务。

### 10.6 DeepSeek 接入与配置归属

模型服务由 Hermes 直接访问，前端不保存 API Key。官方提供 deepseek provider、DEEPSEEK_API_KEY 和 hermes model 配置入口。[S27] 在审定的运行镜像中先完成连接和工具调用冒烟，再接入知卷业务 Adapter；不借助 LangChain 或 LangGraph 转接。

Hermes 原生配置仅写已核查字段，下面是片段而非完整部署配置：

```yaml
model:
  provider: deepseek
  default: REPLACE_WITH_VERIFIED_DEEPSEEK_MODEL_ID
skills:
  write_approval: true
```

占位符必须在部署前替换；不假定 Hermes 会自动展开自定义环境变量。真实密钥通过运行环境的密钥管理注入 DEEPSEEK_API_KEY，不写入 YAML、仓库、浏览器或文档。每个隔离实例独立准备 HERMES_HOME、只读 Skills、工作目录和最小工具权限；此片段本身不建立安全隔离。

configs/business-policy.example.yaml 是知卷业务配置，包含五角色模型映射、修订与预算归属，不能直接复制为 Hermes config.yaml。reference_code/runtime_policy.py 只演示部署配置的拒绝规则，不会调用模型，也不替代网关权限控制。configs/hermes-reviewed-fragment.yaml 只保留 Hermes 原生配置；两类文件必须分开加载。

接入验收需确认：五角色均为 deepseek；实际 model_id 已替换；主调用及必要辅助调用不流向其他供应商；命题与盲解目录互不可读；结构错误拦截；网络重试不叠乘；取消与预算生效；报告标记 SAME_MODEL。详细步骤见附件 docs/06_DeepSeek_Hermes接入指南.md。未通过真实联调前，不宣称已接通。

## 11 任务状态与执行算法

### 11.1 三种状态分开存储

| 对象 | 状态 | 语义 |
| --- | --- | --- |
| 试卷 | DRAFT、PLANNING、PLAN_READY、GENERATING、REVIEW_READY、APPROVED、PUBLISHED、ARCHIVED | 领域生命周期；APPROVED 只表示内容审批，发布还要检查最终产物 |
| 任务 | QUEUED、RUNNING、CANCEL_REQUESTED、CANCELLED、SUCCEEDED、PARTIAL_FAILED、FAILED、TIMED_OUT、BUDGET_EXCEEDED | 执行情况；SUCCEEDED 不等于内容正确 |
| 检查 | PASS、FAIL、REVIEW | 校验结论；不使用布尔 verified 表达所有风险 |

试卷生成任务失败时保留已完成题目，返回缺失槽位和失败阶段。可从已持久化的阶段恢复；不能“继续生成”后悄悄覆盖教师编辑。任务终态与当前试卷 revision 不一致时，旧回调只写历史，不推进新版本状态。

### 11.2 每个槽位的流程

冻结输入和技能版本 → 生成候选题 → 严格结构检查 → 冻结题面与资产 → 独立盲解 → 学科检查与答案比较 → 对照范围和评分规则审查 → 收集可信证据。

若出现可修复 FAIL 且预算和修订次数允许，创建新候选版本并重跑检查；若为工具不支持或证据不足，进入 REVIEW；若命题条件冲突，退回槽位配置；若成功完成全部阶段，进入待教师复核。教师裁决可以解决允许人工处理的 REVIEW，但不能改变原始工具结论。

材料题按依赖有向无环图运行：材料生成并冻结后再并发子题；修改上游材料时取消旧子任务或使其结果失效。整卷检查只接收当前槽位的最新指定版本，不能把第一次生成的题和第三次生成的答案拼接。

### 11.3 队列可靠性

Celery 文档要求关注任务幂等与确认时机，RabbitMQ 的投递确认也不是业务恰好执行一次的保证。[S12][S13] 采用至少一次投递、领域幂等处理。每个阶段使用唯一键 (tenant_id, job_id, stage, slot_id, attempt)，另带输入哈希，重复执行只能产生一个有效领域结果。

API 在一个事务内写 job 和 outbox，独立发布器投递并记录 broker confirm；重投不生成重复 job。Worker 用租约和 fencing token 抢占阶段，完成时检查租约代数，过期 Worker 的结果不能覆盖新结果。队列消息只放标识，不放题目答案和密钥。

模型外部调用无法普遍保证恰好一次计费。请求成功但落库前进程崩溃可能引起重复调用，需记录 provider request_id、请求哈希和 attempt；有供应商幂等支持时使用，无支持时把成本风险显示出来。不要承诺“重试永不重复扣费”。

取消采用持久 cancel_requested_at，阶段边界和每次工具调用前检查；受控进程在宽限期后可终止。收到取消后的迟到结果只存审计，不纳入现行试卷。预算预留和结算采用数据库事务，防止并行任务各自认为还有全部额度。

## 12 专用校验与可信发布门禁

### 12.1 通用检查

检查题面完整、选项 ID 唯一、正确答案引用有效、题型对应答案基数、材料依赖存在、评分点求和、知识点分配、禁止词与不当内容。单选“只有一个被标成正确的选项”只是结构条件；还要检查其他选项语义上是否也正确。判断题与多选题也不能仅凭标签通过。

同卷重复可用规范化文本、数字结构和本卷语义比较，不建立跨历史试卷搜索索引。通过同卷查重不证明全网原创。文字、图片和公式的最终组合必须进入审题；只验证生成器的隐藏表达式不够。

### 12.2 学科规则

| 学科／任务 | 自动检查的适用部分 | 仍需明确的人工或证据检查 |
| --- | --- | --- |
| 数学 | 有理数运算、支持的方程、定义域、单位和等价答案 | 自然语言转式、复杂几何证明、教学方法限制 |
| 物理／化学 | 受控公式与量纲、守恒、数值计算、方程配平 | 理想化假设、实验可行性与安全性、条件适用 |
| 语文／外语 | 题型、文本一致性、材料内证据位置、评分覆盖 | 表达歧义、文学解释、非唯一答案和语言适配 |
| 历史／地理／政治 | 材料内推理、时间一致性、题面与答案冲突提示 | 外部事实、引文、法律政策及时效性；无依据则待核 |
| 作文／论述 | 任务要素、评分维度、分值与档次一致 | 合理观点范围、评分公平性，不做唯一答案检查 |
| 图表／几何 | 坐标、长度等结构约束和图文对应 | 非按比例图的误导、标注重叠与可读性 |

这些检查能力由具体实现和测试决定，不因选用了 SymPy 就自动具备。SymPy 文档明确 parse_expr 使用 eval，不应对未清洗输入使用。[S17] 本系统接收加、乘、幂、有理数、符号、等式等白名单 AST，递归构建表达式；禁止 Python 字符串执行、任意函数、属性访问和动态导入。限制节点数、整数位数、指数、递归深度与运行时间。

### 12.3 检查记录与版本绑定

每条记录保存 check_id、question_revision_id、content_hash、check_code、checker_id/version、evidence_type、status、severity、manual_allowed、evidence_summary、trace_id。来源区分 deterministic、model、human，不合并为不透明质量分。

content_hash 覆盖最终题面、参考答案、评分、相关材料与资产哈希、槽位要求和规则版本。blind_input_hash 只覆盖允许给解题者的输入。修改任一内容生成新 revision，旧证据保留但不可用于新版本发布。可信写入身份来自 mTLS 或内部签名授权，不能由 Agent 填写 checker_id 冒充。

### 12.4 发布条件

发布必须同时满足：槽位完整；当前版本所有必需检查存在；没有未解决 FAIL；所有可人工裁决的 REVIEW 已由授权人员针对相同版本裁决；无过期证据；审核人数、角色分离与签名有效；最终产物预检通过且审批绑定 render_hash；用途策略允许。

第一版采用保守规则：任何 FAIL 都不能通过“忽略”发布。REVIEW 的人工裁决仅适用于 checker 标明可人工处理的项目；结构错误、丢图、错误总分、未授权内容和版本不一致不能裁决绕过。机器结果永远保留为 REVIEW，不伪装成自动 PASS。

发布事务锁定 exam revision，复核审批与文件哈希，写入 immutable snapshot、发布记录与 outbox，再允许获取正式下载链接。失败时不得暴露半套文件。取消发布可以撤销后续链接并标记快照已撤回，但无法保证用户已经下载的副本被远程删除。

## 13 领域数据与存储设计

### 13.1 核心实体

| 实体 | 关键字段 | 约束与用途 |
| --- | --- | --- |
| tenants / users / memberships | 组织、用户、角色 | 用户身份由登录系统确认；组织来自后端授权上下文 |
| exams | id、tenant_id、revision、state、spec_json | 一份试卷项目，不是可供抽题的题库集合 |
| exam_plans | exam_id、revision、slots_json、confirmed_by | 冻结蓝图；确认关联具体配置 revision |
| question_revisions | slot_id、revision、public_json、content_hash | 不可变题面版本；同槽位只指定一个现行版本 |
| answer_revisions | question_revision_id、private_json | 答案、解析、评分点单独保存与授权 |
| assets | exam_id、sha256、kind、storage_key | 图片／图形／材料资源，存储路径不接受模型任意输入 |
| jobs / job_steps | job_type、status、input_revision、attempt、lease | 阶段执行、重试和恢复，不作为发布状态 |
| job_events / outbox | sequence、type、payload、published_at | 可重放进度及事务后可靠消息投递 |
| validation_reports | target_revision、content_hash、check_code、status | 可信校验证据，禁止覆盖历史记录 |
| review_decisions | actor、target_hash、decision、resolution_json | 人工裁决／审批，按当前版本计数 |
| exports | kind、format、source_hash、render_hash、status | 最终文件预检及审核，区分草稿与发布 |
| exam_snapshots | revision、content_hash、manifest_json | 发布时固定题序、答案映射、资产与导出文件 |
| usage_ledger / audit_logs | provider_request_id、usage、cost、action | 成本与操作追踪；普通审计不存题目全文 |

不建立 bank_items、item_search、embedding 或全局题目推荐索引。未来引入题库应新增独立来源适配器和授权记录，不把所有历史草稿自动改成可复用题库。

### 13.2 数据规则

所有业务实体使用服务端生成 UUID；所有组织内关联使用复合外键或等价约束，阻止“本组织题目引用其他组织试卷”。时间统一保存 UTC，界面按用户时区显示；不根据时区推定课程地区。分值采用 x100 整数，金额采用明确币种及定点最小单位，不使用浮点做结算。

Schema 层明确 required、additionalProperties:false、最大长度、数组上限及枚举，避免把大段提示词当成业务对象。字符串中允许 Markdown 文本与受控公式，但禁用原始 HTML、事件处理属性和任意 iframe。JSON Schema 无法表达的跨字段分值求和、ID 关联和课程规则，由领域验证器执行，不能宣称 Schema 自动覆盖。

示例包中的 JSON Schema 使用 Draft 2020-12。实际生产应从 Pydantic 模型导出并在 CI 中比较，接口契约与前端类型保持同源，禁止三份手工定义长期漂移。草稿 SQL 是初始领域设计，不包含完整生产账号授权、所有迁移及备份设置，必须经数据库集成测试后转为 Alembic 迁移。

### 13.3 内容模型

PublicQuestion 保存题型、stem、options、materials、children、assets、score_x100 和公开作答说明；PrivateAnswer 保存 answer_type、正确选项 ID／可接受答案集合、解析、评分点及等价表达。选项字母在显示时由 option_order 生成。填空允许多个 blank_id，评分点可关联 blank_id 或子题。

长材料在题面版本中使用 immutable material_id 引用，材料字节和哈希写入快照。若材料由 AI 生成，provenance 明确标识 ai_generated；教师粘贴原文则标识 user_supplied 与声明来源，不能把声明来源等同已核验。图形资产有自带结构规格与内容哈希，盲解任务拿到与学生相同的视觉内容。

发布 snapshot 包含 spec revision、plan revision、每个 question revision、题序、选项序、所有 asset hash、规则与模型版本、审核记录引用和最终文件哈希。重新排版生成新 export，不修改原快照。学生接口和学生文件使用独立 DTO，从源头不带 private_json。

### 13.4 并发与一致性

读取返回 ETag，例如 "exam-7"。修改、确认蓝图、提交审核和发布必须带 If-Match；缺失返回 428，不匹配返回 412。题目修改生成新 revision 并递增 exam revision，同时将 APPROVED 状态退回 REVIEW_READY，所有依赖当前版本的审批失效。

仅排版参数变化不改变题目语义哈希，但必须使 render_hash 审核失效。课程范围、分值、题干、选项、答案、评分、图片或材料变化均使相关内容检查失效。任务结果持有旧 input_revision 时不得应用到新版本，客户端可查看旧结果并选择人工迁移，不自动合并。

## 14 外部 API 约定

所有路径均为本项目拟开发接口，不是 Hermes 官方 API。前缀 /v1；JSON 请求和响应使用 UTF-8。接口规格见 contracts/openapi.yaml；以下为核心语义。

### 14.1 命令与查询

| 方法与路径 | 作用 | 关键请求／返回 |
| --- | --- | --- |
| GET /v1/capabilities | 查询学段、学科、题型能力 | 能力、适用规则版本、需要人工复核的项目 |
| POST /v1/exams | 新建试卷草稿 | ExamSpec → exam_id、revision、ETag |

首次生成前需要明确蓝图；不提供一个省略校验和审批的 publish=true 便捷参数。前端可以一次编排多个 API 操作，但后端仍逐项检查条件。

### 14.2 请求幂等和错误

所有可能创建任务、审批或发布的 POST 接口使用 Idempotency-Key。以组织、操作者、路径与键建立唯一记录，保存请求体哈希与结果。相同键与相同请求重试返回同一结果；相同键不同请求返回 409。过期策略明确写入接口文档，建议至少覆盖最大任务持续时间和客户端重试窗口。

错误结构统一：code、message、details、trace_id、retryable。典型错误码包括 SPEC_SCORE_MISMATCH、PLAN_NOT_CONFIRMED、STALE_REVISION、BUDGET_EXCEEDED、MODEL_UNAVAILABLE、UNSUPPORTED_CAPABILITY、CHECKS_INCOMPLETE、UNRESOLVED_FAIL、REVIEW_REQUIRED、RENDER_NOT_APPROVED、POLICY_BLOCKED。HTTP 422 表示内容或业务约束不合法，409 表示状态冲突，429 表示请求额度，503 表示依赖暂不可用。

跨组织访问默认返回 404，避免暴露资源存在性；已识别本组织但角色不足可返回 403。401 用于未登录。日志记录 trace_id 和错误码，不回显模型密钥、内部路径或完整第三方错误堆栈。

### 14.3 SSE 事件

事件包括 job.queued、stage.started、question.created、check.completed、repair.started、usage.updated、job.completed、job.failed、job.cancelled。每条事件有 id、job_id、sequence、timestamp、exam_revision 和脱敏 payload。不得推送私有思维链、答案全文或隐藏提示词。

采用同源 HttpOnly、Secure、SameSite Cookie 的教师会话，避免把长期 token 放在 SSE URL。写接口使用 CSRF 防护及 Origin 检查。服务端持久保存事件并按 sequence 重放；客户端用 sequence 去重。断线只断观察连接，不取消任务。游标过期返回 410，客户端读取任务快照后从新的 sequence 继续。

建议每 15 秒发送心跳、反向代理关闭 SSE 缓冲并设置适当空闲超时。开发验收必须模拟断线、重复事件、乱序回调和过期版本。事件传输成功不等于任务完成，以领域状态为准。

开发环境配置和 provider 密钥通过本地未提交 .env 管理。附件 infra/compose.yaml 只启动 PostgreSQL 与 RabbitMQ，不能误认为一条命令即可运行完整产品。业务服务实现后再补自己的 Dockerfile、应用配置和健康探针。

每次提交执行类型检查、单元测试、Schema／OpenAPI 校验、SQL 迁移测试、静态安全扫描与关键端到端测试。数据库迁移采用 expand／migrate／contract，先兼容新增字段，再迁移数据，最后移除旧字段；禁止运行中改变已发布快照。

## 16 排版与交付文件规范

使用统一内容 AST 渲染：段落、公式、表格、列表、图片、题号、选项、答题空间、评分点。学生与教师版共享题面渲染器，但使用不同的服务端数据投影。KaTeX 采用 trust:false 和输入长度限制；启用原始 HTML 会破坏这条边界，不能依赖公式库替整个页面消毒。[S18]

PDF 由固定 Playwright／Chromium 镜像生成，采用 print CSS，主模板默认 A4。[S19] 等待字体加载、公式排版和图片 decode 完成；超时或字体缺失则失败，不交付一份缺字文件。共享素材通过本地资源代理加载，渲染器默认阻止外部网络和 file:// 任意读取。

预检至少包括：总题数与编号、总分、学生内容无答案节点、所有资产加载成功、公式未报错、正文未溢出边界、材料与子题有清晰关联、过长题目可合理跨页。单题超过一页时不能硬设置整体 break-inside:avoid 导致裁切；须按子段落或子题拆分。

DOCX 使用独立模板与转换测试。优先原生文本及可编辑公式；复杂公式回退为高清图形时，导出信息需说明其不可像普通文本编辑。DOCX 与 PDF 分页不同属于需说明的渲染差异，不是可以忽略内容缺失的理由。中文字体文件只在服务器合规使用，不随源代码随意分发。

导出 JSON 默认只有组织内教师可以下载完整答案版本；学生 JSON 不带答案、解析和私有证据。离线 HTML 必须自包含必要样式与资产，不依赖外部 CDN。正式产物记录 AI 生成来源及适用标识要求，标识本身应按运营场景完成合规核查。[S23]

# 第四部分｜测试验收、运维与交付计划

## 17 安全与治理

### 17.1 信任边界

把教师输入、模型文本、工具返回中的外部内容、图形描述及素材都当成不可信数据。只有认证服务确定身份，业务后端确定权限，可信检查器写证据，发布事务决定最终状态。模型不能自报“我是管理员”“已经人工批准”改变授权。

不将业务数据库、主模型密钥、对象存储主密钥或宿主机挂载传给工具执行环境。Agent 运行目录和 HERMES_HOME 按任务隔离；盲解不能继承作者的 AGENTS.md、会话历史或私有文件。Hermes 提供容器等隔离机制，但仍需本应用配置网络、权限和凭据边界，不能仅安装框架就视为安全。[S05]

### 17.2 核心威胁与控制

| 威胁 | 防护设计 | 必测场景 |
| --- | --- | --- |
| 提示注入 | 文本不能扩大工具授权；只读规则、固定 Schema、服务端字段绑定 | 题干要求读取答案文件／泄露密钥，必须失败 |
| 跨组织访问 | 服务端鉴权、复合关联、RLS、私有资源代理 | 修改 UUID、伪造 tenant_id、猜测下载地址 |
| 盲解答案泄露 | 独立实例、不同目录与授权、无共享搜索／记忆 | 在作者私有区埋唯一标记，盲解无法读取 |
| 任意执行 | 禁用自由终端；白名单 AST；沙箱限额 | import、属性访问、超大指数、无限递归 |
| XSS／SSRF | 内容消毒、SVG 安全处理、渲染禁外网 | onload、script、外链图片、云元数据地址 |
| 证据伪造 | 检查器身份验证、不可变记录、hash 绑定 | Agent 填 verified:true 或伪造 checker_id |
| 费用失控 | 预算预留、调用／迭代／并行上限、硬截止时间 | 并行抢占预算、异常无限重试 |
| 旧审批复用 | revision、content_hash、render_hash 原子检查 | 修改答案后带旧审核记录发布 |
| 供应链风险 | 锁版本、只读 Skills、依赖扫描、镜像摘要 | 启动时自动更新／下载未审 Skill 被阻止 |

RLS 需特别注意：PostgreSQL 的超级用户及 BYPASSRLS 角色可绕过策略，表拥有者通常也可绕过。[S14] 生产 API 账号不得使用这些权限；迁移账号与运行账号分开。每个事务使用经鉴权的 SET LOCAL 组织上下文，连接复用后不可残留上次组织。RLS 不能限制同租户内的答案角色权限，后者还需要服务层与数据库授权。

### 17.3 数据保留与隐私

默认不采集学生身份与成绩。建议草稿与工作区提供可配置保留期限；短期运行目录任务结束后清理，审计与发布快照按组织政策保留。保留期限属于业务选择，需要组织确认，不是本文件声明的法定时长。

普通日志只记录对象 ID、版本、阶段、耗时、用量和错误码。含题面或模型响应的调试记录默认关闭，需要受限审批才能短期开启。备份加密、下载访问、密钥轮换和跨区域模型传输需要单独配置。删除操作解释清楚活动存储、备份到期和已下载副本的不同边界。

中国大陆公众服务的适用范围、输入记录保护及生成内容标识应按实际部署核查。[S22][S23] 学校日常考试策略应依据主管部门要求维护版本，不能把配置界面当成制度豁免工具。[S21]

## 18 测试体系与发布标准

### 18.1 测试分层

单元测试覆盖分值、状态迁移、答案 ID、哈希、幂等与发布门禁。契约测试覆盖合法与非法 JSON、接口状态码、学生投影与 API 类型一致。集成测试使用真实 PostgreSQL／RabbitMQ，验证迁移、RLS、重复投递、进程崩溃与 outbox 恢复。端到端测试覆盖三个学段、客观题、主观题、材料题与图形题。

模型质量测试与软件测试分开。确定性测试每天或每次提交运行；成本较高的真实模型回归在模型／Skill／规则／重要代码变化时运行。测试材料由教师和开发共同构建，只用于隐藏评测，不作为生产题库，不放进命题 Agent 上下文。每条样例记录预期能力和错误原因，避免拿未审核的“标准答案”测试验证器。

### 18.2 必需的负向测试

| 测试编号 | 输入或故障 | 预期结果 |
| --- | --- | --- |
| T-01 | 单选两个选项等价，如 0.5 与 1/2 | 不以答案字段单一为由通过，生成问题记录 |
| T-02 | 题干丢失条件导致多解 | FAIL 或 REVIEW，不自行补条件当成原题 |
| T-03 | 评分点合计不等于题分 | 硬拦截并显示差额 |
| T-04 | 100 分配置实际只分配 96 分 | 模型调用前返回 SPEC_SCORE_MISMATCH |
| T-05 | 作者答案 B，独立解答得到 C | 拦截并修订／复核，不投票强行通过 |
| T-06 | SymPy 不支持或超时 | REVIEW，不能默认 PASS 或“无解” |
| T-07 | 同一道题改了数字但沿用旧报告 | 证据过期，发布失败 |
| T-08 | 题干写“如图”但素材缺失 | 不允许正式导出 |
| T-09 | 打乱选项 | 按稳定 ID 重建答案映射，学生版不带答案 |
| T-10 | 阅读材料修改 | 所有关联子题证据失效 |
| T-11 | Worker 完成模型调用后崩溃 | 恢复不重复写题；记录可能重复调用成本 |
| T-12 | 重复消息／迟到回调／旧租约 | 不覆盖新 revision，无重复领域结果 |
| T-13 | SSE 断线重连 | 按序号恢复，不重启动生成 |
| T-14 | 取消后供应商迟到返回 | 不进入现行试卷，仍记录实际费用 |
| T-15 | 作者私有目录含唯一答案标记 | 盲解不能访问，访问尝试被记录 |
| T-16 | 老师编辑与重生成同时完成 | 乐观锁冲突，保留双方版本供确认 |
| T-17 | Agent 输出已批准／篡改检查器 | 发布权限不变化，拒绝伪造证据 |
| T-18 | 跨租户读取答案或导出文件 | 404／403，不泄露内容或对象存在性 |
| T-19 | 小学课程限制与高级解法冲突 | 教学适配待复核或失败，不因答案正确放行 |
| T-20 | 开放题出现多个合理观点 | 评分范围明确，不误判为单一答案冲突 |
| T-21 | 当前事实或名人引文无依据 | 标记待核，不生成伪造参考链接 |
| T-22 | 学校日常考试模式低年级纸笔考试 | 按适用策略阻止，不影响合法练习功能 |
| T-23 | 审批通过后换了字体／模板导致裁切 | 原 render_hash 审批失效，需要重检 |
| T-24 | 并行模型请求同时接近预算 | 原子预留，不突破允许的在途预算边界 |

每个负向样例都需要控制组，防止系统通过“把所有题都判待审”取得表面安全。验收同时看误放与误拦。

### 18.3 指标定义

| 指标 | 精确定义 | 建议验收方式 |
| --- | --- | --- |
| 已发布硬约束违规数 | 正式发布后分值、编号、版本或必需流程违规 | 发布回归为 0；发现任何一例阻断上线 |
| 自动筛选严重错误漏放率 | 盲评中被自动检查标为可送审的题里，仍含严重错误的比例 | 分学段／学科／题型报告，不能用人工改完后的结果作分母 |
| 误拦率 | 审定正确样例被自动标 FAIL 的比例 | 与错误拦截率一起评估 |
| 首轮可用率 | 生成后无需实质改题、仅常规确认即可使用的题占比 | 区分格式修改与实质内容修改 |
| 教师修改成本 | 每套卷实质修改题数与有效审核操作时长 | 按题型和学段分别统计 |
| 每道可用题成本 | 全部生成、检查、失败、修订费用除以最终可用题数 | 不能只计算第一次调用成本 |
| 完整交付率 | 在指定预算和输入规格内完成所有槽位与导出的任务比例 | 模型／工具失败计入，不排除难题 |
| 证据完整率 | 必需检查、人工裁决与产物审批能关联当前版本的比例 | 正式发布要求 100% |

严重错误包括答案错误、条件不充分且影响作答、客观题非预期多解、关键事实错误、明显超出声明范围、评分规则无法使用。样本由盲评教师判定，不以生成模型自己评分为真值。

初始评测建议为每学段至少 100 道新生成候选题及覆盖全部关键失败模式的专项样例，并至少各做一套综合试卷端到端测试；这是发现问题的起点，不能证明低至 1% 的错误率，更不足以覆盖所有学科。公开宣称某细分能力达到某错误率之前，必须增加对应分层样本、报告分母和不确定性。

对于独立同分布的理想随机样本，零错误时可用 1-0.05^(1/n) 计算单侧 95% 二项上界；n=100 时约为 2.95%。实际题目通常具有模板、知识点和教师聚类相关性，所以不能机械把这个公式当作全平台保证。

## 19 性能、成本与资源配置

### 19.1 初始工程目标

以下均为规划目标，需压测后修改：不含模型等待的普通 API 在约定负载下 P95 小于 500 毫秒；任务提交 P95 小于 1 秒；事件写入后到前端显示 P95 小于 2 秒；常规文本／公式试卷导出 P95 小于 30 秒。测量必须注明硬件、并发、题数、素材大小和供应商区域，不能将目标写成已实现性能。

模型生成不承诺固定时长。显示真实进度、调用耗时和失败原因，并设置可配置任务截止时间；大型综合卷允许教师拆分配置，而非无限增加上下文。前端不能把网络超时解释为整卷任务已失败。

开发／小规模验证可从应用与 Worker 合计 4–8 vCPU、16 GB 内存起步，数据库与消息队列按资源隔离部署；这只是待压测的容量起点，不是生产容量保证。使用托管模型时无需因本产品默认采购 GPU。并行度初始限制为每组织 2 个整卷任务、每卷 3 个题组，按供应商配额和实测成本调整。

### 19.2 成本模型

每次调用费用 = 输入 token × 输入单价 / 1,000,000 + 输出 token × 输出单价 / 1,000,000 + 工具／图像等计费。每套卷费用为所有角色、所有尝试、失败调用及渲染资源费用之和；人工审核成本单列。模型供应商的缓存、推理 token 和失败计费以实际账单规则为准，不假定所有服务相同。

示意计算：假设某次任务共 140,000 输入 token、50,000 输出 token，且内部测试假设价分别为每百万 6 元和 18 元，则模型部分为 1.74 元。这只是演示公式的假设，不是任何供应商报价，也未包含其他费用。生产 pricing 表必须保存币种、生效时间、模型与来源，由管理员维护。

预算在创建任务时预留，每次调用前按最大允许输出做费用上界预留，返回后结算并释放差额。用量缺失时保留待核费用，不记为零。教师主动提高预算形成审计事件；Agent 不能自行修改预算或选择未经批准的更贵模型。

## 20 部署、监控与故障处置

### 20.1 环境与发布

开发、测试、生产使用不同数据库、对象存储桶、模型凭据和 Hermes 目录。所有镜像固定摘要，Skills 与规则包固定哈希；更新应用不能自动 hermes update。先在测试环境跑三学段模型回归与数据恢复，再灰度少量任务，监控错误与成本，最后扩大流量。

升级保持在途任务继续使用原运行版本，或显式取消后创建新任务；不得在任务中途热替换提示词。数据库先兼容扩展，再部署新服务。回滚应用与 Skill bundle 可使用历史镜像；涉及不可逆数据变化时需要经过演练的恢复或前向修复方案。

### 20.2 观测与告警

使用 trace_id 串联 API、job、stage、provider request、checker 和 renderer；OpenTelemetry 可承载 trace、metric、log 的统一观测。[S20] 必需指标包括队列等待、阶段耗时、模型429／超时、无效JSON、修订轮数、REVIEW 比例、预算拒绝、渲染失败、取消延迟和证据过期。

以下事件建议高优先级告警：任何正式发布缺失必需证据、跨组织访问成功、学生文件出现答案、盲解读到作者私有数据、预算控制被绕过、发布文件哈希不一致。模型质量下降与供应商限流区分处理，不通过放宽审核门槛缓解。

### 20.3 故障运行手册

DeepSeek 不可用：暂停新任务并显示故障，等待恢复；首版不自动切换模型或供应商。Worker 崩溃：由租约到期恢复，旧结果被 fencing 阻止覆盖。队列故障：outbox 保留，恢复后重新投递。数据库故障：停止发布和新任务，不以本地临时记录代替审批。

检查器或排版器故障：停止对应阶段，不将“检查未执行”写成通过。已发布试题确认有误：将快照标记撤回、关闭后续下载、定位受影响组织、生成更正记录；修订生成新快照并重新审批。已下载文件无法可靠远程撤销，需组织通知使用者。

备份覆盖 PostgreSQL、私有资产、发布文件、规则 bundle 与版本清单；运行临时目录通常不需要长期备份。建议恢复目标初值 RPO 24 小时、RTO 4 小时，仅作演练目标；正式值由使用方确认并通过恢复实测，不在没有演练时宣称保证。

## 21 交付拆解与职责

| 工作包 | 主要交付 | 依赖与验收门 |
| --- | --- | --- |
| W1 范围与契约 | PRD、课程字段、能力矩阵、Schema、状态机 | 明确全学段与无题库；所有发布阻断规则有归属 |
| W2 业务闭环 | 登录、版本、蓝图、队列、SSE、编辑、mock 导出 | 小学／初中／高中都跑通；模拟状态标识明确 |
| W3 Hermes 适配 | 固定提交、五个 Skills、受限工具、盲解隔离 | 真实模型接口冒烟、取消和泄露负向测试 |
| W4 校验与修订 | 通用／学科检查器、有限修订、人工裁决 | FAIL／REVIEW 不混淆；旧证据无法发布 |

| W6 安全与质量 | 三学段评测、负向回归、负载、故障恢复 | 首发承诺清单全部验收，已知严重缺陷为 0 |

这些是依赖顺序，不是“先做小学、以后再做高中”。可并行建设各学科规则包，但共享相同的安全与发布基础。每个工作包只有达到验收门后才能替换 mock 或开放正式功能。

M0—M3 的阶段退出条件、G-MIN 与 G-FULL 的可执行验收规程见第 24—28 章。原有 W1—W7 是工作包，不能用 mock 完成代替真实接入验收。

建议角色配置：产品负责人负责范围和验收口径；前端负责人负责编辑与可访问性；后端负责人负责状态、数据、权限与发布；Agent 工程师负责 Hermes 适配、Skills 和工具；学科负责人负责三学段学科规则及盲评；测试与运维负责回归、安全、恢复和发布。小团队可兼任，但正式审核与命题角色按适用制度分离。

## 22 架构决策记录与上线前必填项

ADR-01：不引入题库和向量检索，历史成果不进入 Agent 长期记忆。ADR-02：DeepSeek 为首发模型服务，Hermes 为唯一 Agent 框架，经薄 Adapter 集成，不引入 LangChain、LangGraph；业务状态由后端拥有。ADR-03：盲解用独立运行实例和工具权限，而非默认子代理共享环境。ADR-04：PASS／FAIL／REVIEW 与人工裁决分开。ADR-05：采用同源数据与不可变发布快照。ADR-06：队列至少一次投递、阶段幂等，外部计费不承诺恰好一次。ADR-07：生产 Skills 只读，更新经过测试与审批。

上线前必须填写且审定：实际课程地区与学制；首发学科／题型清单；教师审核策略与用途限制；DeepSeek 实际 model_id、工具调用模式和数据条款；Hermes 固定提交与运行镜像；预算／并行／超时配置；软件依赖版本清单；数据保留与删除规则；内容标识与服务合规要求；容量压测和恢复报告。

这些是部署参数与发布条件，不影响本文件作为开发基线使用。未确定的项目不能由开发人员或模型随意填成“支持全部”“永久免费”或“自动正确”。

## 23 附件如何交给开发团队

先阅读产品需求与技术选型，再以 contracts 中的 Schema 与 OpenAPI 作为前后端接口讨论基线；数据库草案转为迁移并做真实 PostgreSQL 测试；五个 Skill 模板在固定 Hermes 提交上加载验证；reference_code 的发布门禁示例用于理解规则并扩展，不直接替代完整鉴权和数据库事务。

新增 `acceptance/` 为验收材料入口；所有运行状态默认 NOT_RUN。第 24—28 章明确哪些效果属于当前设计包，哪些必须由后续可运行工程交付。

附件附有可执行的契约样例验证与发布门禁单元测试。测试通过只能说明这些样例与参考规则内部一致，不能说明 Hermes 已集成、全学科答案已正确或生产环境已安全。完整应用、真实模型评测、渲染生产管线及运维部署仍需要按本文实现与验收。

# 第五部分｜MVP 阶段、验收链路与可交付效果

## 24 MVP 分阶段范围与退出条件

### 24.1 本次文档交付不等于应用完成

**本次 v1.2 新增的是开发阶段划分、验收规程和交付清单，不是已经开发完成的 MVP。** 当前 ZIP 仍为设计、契约、Skills 模板、参考规则及离线测试材料；没有 Hermes 官方源码、可启动的完整前后端或真实 DeepSeek 调用结果。`HermesAdapter(Protocol)` 仅定义接口。MVP 是否完成，以本部分的真实运行证据及签字记录为准，不能以文件数量、截图或本地单元测试数量代替。

第一版路线继续固定为 **DeepSeek 官方 API + Hermes 唯一 Agent 框架**；不引入 LangChain、LangGraph，不接题库，不使用历史试卷检索或模型长期记忆。小学、初中、高中从 M1 起同时参与验证；阶段是工程完成度的递进，不是“先小学、以后再初高中”。

`v1.2` 是本文及交接材料版本；`M0—M3` 是未来产品研发阶段，两者不能混用。以下阶段与指标均为建议验收基线，并非已测成绩。

### 24.2 阶段计划：先能运行，再能使用，再可受控交付

| 阶段 | 主要开发与交付内容 | 退出条件与可宣称效果 |

M1 的 `health()` 必须来自实际运行环境，不能把配置中填写的提交号直接当作运行证明。交付证据至少包含实际 Git 提交或镜像来源、依赖锁文件、配置摘要、启动记录及真实调用记录；密钥不进入文档、镜像或 ZIP。

### 24.3 各阶段技术范围与依赖

React、FastAPI、PostgreSQL、Hermes 薄 Adapter 及服务端 DeepSeek 从 M1 开始接通。推荐从 M1 使用 Celery + RabbitMQ；仅内部骨架允许暂用独立单 Worker，但必须具备任务记录、失败状态和幂等边界，不能把长任务放进普通请求或用浏览器计时器假装后台运行。M3 必须落实第 08—11 章选定的队列与恢复机制，或先批准架构变更。

M2 的检查下限为：结构合法、分值一致、答案引用有效、评分点完整、盲解冲突可见，以及所选数学样例的一个真实计算检查器。检查器不支持时返回 REVIEW；没有工具能力不能显示“全部校验通过”。M3 再完成首发能力清单所需的检查与人工复核程序。

M2 必须输出真实 PDF 与 JSON，Word 可编辑试卷导出在 M3 验收。这里的“PDF／Word”指未来应用生成的试卷，不是本交接包中的产品说明文件。原型 HTML 或文档 HTML 不等于前端工程；必须交付页面源代码、依赖清单、构建与运行入口。

与原工作包对应：M0 对应 W1；M1 对应 W2 的运行基础与 W3 的真实接入；M2 对应 W2—W5 的最小纵向闭环；M3 完成 W3—W7 及全部首发承诺。不能用局部 mock 通过 W2，直接宣称 M2 已验收。

### 24.4 不变范围、暂缓范围与能力登记

全学段是固定范围；具体学科、题型、图文与导出支持沿用第 03 章，并在开工时逐项登记。M2 用三个学段的数学小卷验证工程链路，不等于把最终产品缩成数学工具。M3 必须遍历已承诺的全部“学段 × 学科 × 题型”组合；未验收的组合不得标记 READY，更不能在测试失败后偷偷从承诺清单移除。

每个组合分别记录生成、检查、渲染能力和人工复核规程。开放题允许“生成与导出可用，语义检查需教师复核”，但不能把 REVIEW 原始结果改为自动 PASS。未支持的听力、视频、实作等任务明确禁用或仅输出有标识的文字草稿，不用“可自定义学科”冒充完整支持。

题库、RAG 检索、学生账号、在线考试、自动批改、排名、支付、模型微调和严格 A/B 等值仍不在第一版；课程配置与验收用例是软件输入和测试材料，不是题库。历史版本只用于编辑、恢复和审计。

## 25 最小验收链路 G-MIN：真实跑通，而不是演示动画

### 25.1 进入条件与固定样例

由未参与实现的测试人员或交付接收者，在干净环境按 README 操作。真实 Hermes、服务端 DeepSeek 凭据、实际 model_id、数据库、Worker 和导出环境必须就绪；只允许单元测试使用 mock。先确认测试预算、授权账户和用途为受限练习验证，不发布学校正式考试。

每个学段使用一套 **5 题、20 分**的小卷：单选 2 题，每题 3 分；填空 2 题，每题 2 分；解答 1 题，10 分。三个学段合计至少 3 套、15 道真实生成题。这只是工程冒烟规模，不是质量样本量。

| 测试输入 | 示例范围与方法限制 | 需要观察的差异 |
| --- | --- | --- |
| 小学四年级数学 | 教师已确认的整数四则运算；禁止把方程作为必要解法 | 数值、阅读负担和解法适配；不因算对就默认适教 |
| 初中七年级数学 | 教师已确认的一元一次方程及应用；排除未教二次方程 | 条件充分、解集与应用情境一致 |
| 高中一年级数学 | 教师已确认的集合与不等式基础；不使用微积分 | 定义域、边界和答案表达完整 |

这些是人工确认后的验收配置示例，不声称对应某教材章节。包内 `acceptance/fixtures/` 只保存命题要求，不预置要生成的题目或标准答案。模型每次输出可以不同，不比较题目文字是否与录屏相同。

### 25.2 最小成功链路：12 个检查点

| 用例 | 操作与系统行为 | 通过证据 |
| --- | --- | --- |
| MIN-01 启动与配置 | 按说明启动前端、API、数据库、Worker、Hermes 和渲染器；配置密钥只在服务端 | 实际健康检查、运行版本及脱敏启动记录；不是只启动数据库和队列 |
| MIN-02 三学段输入 | 分别填写上述三套规格；确认知识点和用途 | 保存三份 spec；20 分、5 个叶子题；不能自动扩大范围 |
| MIN-03 计划确认 | 显示逐题考查目标、题型、分值；教师确认后开始 | blueprint 版本与确认记录；未确认不产生正式生成任务 |
| MIN-04 真实命题 | 网页提交后返回 job_id；Worker 经 Adapter 调用 Hermes，再调用 DeepSeek | 可关联的任务、Hermes 运行和供应商调用记录；输出来源为 live，非固定模板或直接绕过 Hermes 调模型 |
| MIN-05 进度与刷新 | 显示已生成／待检查／修订题数；刷新或重连页面 | 同一 job_id 恢复进度，不重复生成；后台事件与页面一致 |
| MIN-06 基础检查与盲解 | 对最终题面独立求解；执行结构、分值、答案引用和所选数学计算检查 | 两个隔离任务输入摘要、实际工具记录、PASS／FAIL／REVIEW；同模型标记 SAME_MODEL |
| MIN-07 问题修订 | 通过受控故障样例触发一次错误，修改或退回；最多两轮内容修订 | 每轮有原因、版本和新检查；超限进入待审，不无限重试 |
| MIN-08 手工编辑 | 教师改一处题干数字或评分点并保存 | revision 增加、旧检查失效；重新检查当前题面 |
| MIN-09 单题重生成 | 保留该题槽位的目标、题型和分值，重新生成一题 | 只替换当前题；其他题不变化；迟到结果不能覆盖教师更新 |
| MIN-10 保存与复核 | 关闭再打开项目，查看答案、解析和未解决问题 | 数据持久化；教师确认绑定当前版本；失败题不能直接算已完成 |
| MIN-11 草稿交付 | 从同一快照导出学生 PDF、教师 PDF 和 JSON | 真实可打开的文件；版本一致；草稿标识清楚；学生文件不含私有答案 |
| MIN-12 证据归档 | 整理三个学段的运行、文件与异常记录 | 三学段各一条完整成功链路；必需检查点不缺失；状态由执行人签署 |

真实调用证据优先包含供应商 request_id；接口未提供时，保留服务端 trace_id、端点与模型、请求／响应摘要及用量记录，并注明无法获取供应商 ID。只给一张“生成成功”截图不能证明真实接入，也不要求为验收保存模型私有推理过程。

MIN-07 的受控故障必须标记为测试注入，不能冒充模型真实错误率。它用于确认错误处理；真实生成链路 MIN-04、MIN-06 仍必须使用实际服务，不能让整个流程自动退回到模拟题。

### 25.3 最低失败链路：不能只测成功

| 用例 | 注入条件 | 必须出现的结果 |
| --- | --- | --- |
| MIN-N01 缺少或无效密钥 | 删除凭据／使用无效凭据后生成 | 缺少凭据在调用前拒绝；无效凭据显示明确鉴权失败；不返回假题、不泄露密钥 |
| MIN-N02 规格矛盾 | 总分 20，但题型分值之和为 18 | 在模型调用前拒绝；页面显示差额 |
| MIN-N03 无效生成结果 | 注入缺题干、非法 JSON 或无效答案引用 | 有限格式修复或失败；非法结果不进入可用试卷 |
| MIN-N04 检查未完成 | 令检查器超时或返回不支持 | 显示 REVIEW／故障，不写 PASS；保留待核项 |
| MIN-N05 旧证据 | 改题后使用修改前的检查或审批 | 版本过期；拒绝确认／正式发布；允许有明确标识的受限草稿 |
| MIN-N06 取消与迟到 | 运行中取消任务，随后模拟供应商迟到返回 | 不再安排新调用；迟到内容不写入当前卷；已发生用量保留待核或实际值 |
| MIN-N07 答案泄露 | 检查学生 API、HTML、PDF 与资源 | 不包含私有答案、解析或评分字段；不能只靠 CSS 隐藏 |

G-MIN 通过要求：12 个成功检查点在三个学段分别执行，7 个失败用例执行并留证；MIN-N05、MIN-N07 必须在三学段导出与编辑链路复测。任一适用必测项为 NOT_RUN、BLOCKED 或 FAIL，则 G-MIN 未通过。M2 通过仅表示真实的受限验证闭环，不能直接开放正式发布。

## 26 完整验收链路 G-FULL：从部署到可追溯交付

### 26.1 主链路及范围

**完整链路 = 可复现部署 → 权限与范围 → 蓝图 → 真实生成 → 隔离盲解 → 工具证据 → 有限修订 → 编辑与重检 → 整卷审查 → 教师审批 → 最终文件预检 → 发布 → 下载与追溯 → 故障恢复及撤回。**

所有正式产物必须绑定同一快照与已批准的文件哈希。原始检查 FAIL 需要修正或删除题目后重检；REVIEW 可由授权教师按规程裁决，但原始自动结果仍保留 REVIEW。命题 Agent 无发布权限，审核人数和角色分离按已确认的使用策略执行。

基线先做三学段各一套数学综合卷和一套阅读／材料型卷，共至少 6 套完整卷，覆盖客观题、分步解答、共享材料与开放性评分。它们是跨学段／跨检查方式的下限，不替代首发清单；每个已承诺组合还必须出现在对应端到端验收记录中。

综合卷可使用 100 分配置；具体题数、时长和课程范围由学科负责人确认。材料卷需验证材料与子题依赖、父题不重复计分；开放题需验证评分标准能容纳不同合理答案。图形题只要在承诺清单中，就必须检查真实图形资产，不能用纯文字卷替代图形验收。

### 26.2 功能、内容和交付检查点

| 用例 | 完整验收动作 | 不可妥协的通过条件 |
| --- | --- | --- |
| FULL-01 干净环境复现 | 从交付源码、锁定依赖和配置安装启动 | 前后端、数据库迁移、队列、Hermes、渲染全部可用；无开发者私有文件依赖 |
| FULL-02 范围与权限 | 按首发清单进入三学段；验证教师、审核人、管理员身份 | 未支持能力不伪装可用；按权限显示答案、审核和下载 |
| FULL-03 规格与蓝图 | 校验输入并确认；变更范围后再次提交 | 分值、题型、知识点归属可核对；已确认计划不可静默更改 |
| FULL-04 真实生成追踪 | 五个 Skills 经真实 Hermes 工作，记录每道题来源 | 固定模型／提交／Skill 版本；无直接模型旁路或隐式题库；输出可追踪 |
| FULL-05 盲解隔离 | 作者区设置秘密标记；测试盲解文件、工具、历史访问 | 盲解没有参考答案访问权；独立运行证据齐全；不能仅凭答案里未出现标记判定隔离成功 |
| FULL-06 检查器证据 | 触发数学、分值、答案引用和素材等检查 | 结果由受信服务写入，绑定当前内容；Agent 自报 verified 无效 |
| FULL-07 有限修订 | 触发答案冲突、条件缺失及修订超限 | 修改后重检；不能投票强行通过、擅自补条件或放宽规则 |
| FULL-08 教学与开放题 | 教师独立复核小学方法、高中边界和开放题评分 | 超范围问题可定位；合理多答案不被当作唯一答案错误；REVIEW 有人工依据 |
| FULL-09 编辑与并发 | 改题、换题、改材料并与重生成并发 | 新版本、证据失效及乐观锁有效；共享材料变更使关联子题重检 |
| FULL-10 整卷审查 | 核对题数、总分、知识点、重复和答案泄露关系 | 无硬约束错误；不足时明示并请求调整，不能静默减题或越界 |
| FULL-11 人工审批 | 使用已配置的审核角色与人数批准当前内容 | 自审限制生效；未闭合 FAIL 阻断；REVIEW 裁决与自动结果分开保存 |
| FULL-12 产物预检与发布 | 生成受限最终文件，预览并批准，再发布同一文件 | content_hash 与 render_hash 绑定；改模板、字体、图或答案后旧审批不能复用 |
| FULL-13 PDF／DOCX／JSON | 打开学生卷、教师卷、评分细则和可编辑 Word | 题号、选项、公式、图形、分页与评分一致；数学公式的编辑方式按承诺验收，不能把整页截图称可编辑 Word |
| FULL-14 下载、审计与撤回 | 授权下载、查询历史、撤回一份测试发布 | 仅授权身份获取产物；有版本与事件记录；撤回关闭后续访问并发更正通知，说明已下载副本无法远程删除 |

学生卷可以出现题干本身需要的例题或阅读答案情境；隐私检查针对被错误混入的私有答案与评分数据，不能简单禁止某个正确数字出现在学生卷。验收需结合字段检查、隐藏标记和人工预览。

### 26.3 稳定性、安全、费用与运维检查点

| 用例 | 故障或攻击动作 | 预期行为与证据 |
| --- | --- | --- |
| FULL-15 投递与崩溃 | 重投消息、Worker 调用后崩溃、outbox 恢复 | 不重复写入领域结果；旧租约不能覆盖新版本；可能重复计费如实记录 |

### 26.4 质量、性能与发布判定

内容评估的建议下限为每学段至少 100 道新生成候选题；每个承诺组合至少 20 道，组合较多时总样本应随之增加。记录第一轮、修订后和教师审核后的三个结果，不能仅展示最终改好的题。新增测试材料不得被命题 Agent 检索到。

| 门槛 | 建议判定规则 | 证据与限制 |
| --- | --- | --- |
| 硬错误与权限 | 所有必测发布、安全、泄露与版本检查通过；无未关闭 P0／P1 缺陷 | 任意一次越权、学生私有答案泄露、无证据发布等均阻断交付 |
| 证据完整 | 正式发布所需证据及审批关联当前版本，完整率 100% | 不允许拿旧哈希、示例记录或 Agent 自报结果补数 |
| 首轮可用率 | 受控试用初始目标：三学段分别至少 80% | 定义为首次生成后无需实质改题、仅常规确认即可使用；教师判定；目标需在运行前确认 |
| 完整交付率 | 受控试用初始目标：三学段分别至少 90% | 在预先限定的预算、时限、修订次数内完成；有效提交后的模型故障也计入分母 |
| 自动筛选风险 | 必须报告严重错误漏放、误拦和 REVIEW 比例 | 不以“全部转人工”掩盖检查无效；允许上限需由学科负责人在评测前签定，未签不能通过 |
| 性能与成本 | 沿用第 19 章的待测初始目标，冻结硬件、并发、题数及预算 | 形成真实报告；模型延迟不承诺固定值；未测记 NOT_RUN |

80%、90%及样本下限是本项目建议的初始试用目标，不是行业标准或当前实测值；所有阈值须在评测前签署，不能看到结果后改成刚好通过。样本有限，零个已知错误不证明未来零错误。全学段覆盖也不等于全学科自动验证能力相同。

G-FULL 通过需要：G-MIN 已通过；所有适用完整用例通过；首发清单无未验收承诺；统计与缺陷报告齐全；运行、教研和测试负责人签字。对于预先未承诺的能力，可记录 NOT_APPLICABLE 并附事先批准的范围依据；不得用 NOT_APPLICABLE 排除三学段、真实模型接入、盲解隔离、权限或必需发布检查。

## 28 验收执行、证据和签收规程

### 28.1 执行顺序与负责人员

先由产品与学科负责人冻结首发能力及阈值，技术负责人固定提交和模型；随后测试人员在干净环境执行 M1 冒烟与 G-MIN，再执行 G-FULL 的成功、失败、安全和恢复场景。模型或 Skill 发生变更时，重跑对应内容回归；权限、版本、预算或导出变更时，重跑相关阻断与文件测试。

每条用例记录实际执行人、时间、环境、输入、job_id、内容版本、结果和证据。产品负责人确认需求效果；学科负责人确认教学与评分；技术负责人确认真实集成；测试负责人确认复现和缺陷；运维负责人确认启动、监控与恢复。多人可兼任开发职责，但正式命题审核仍按第 02 章及适用策略分离。

### 28.2 状态、证据与缺陷规则

| 状态 | 含义 | 是否计为通过 |
| --- | --- | --- |
| NOT_RUN | 尚未执行或只完成文档／单元测试 | 否 |
| RUNNING | 正在执行，结果未完成 | 否 |
| PASS | 实际结果符合预期，版本一致且证据完整 | 是 |
| FAIL | 结果与预期冲突 | 否，修复后重测 |
| BLOCKED | 环境、凭据、依赖或前置条件不足 | 否，不能用口头承诺替代 |
| NOT_APPLICABLE | 不在事先批准的能力与用途范围内 | 不计通过；需书面范围依据，固定核心项不可豁免 |

证据分级保存：公共交付只含脱敏摘要与哈希；受限审题证据可含题面、参考答案及盲解输入；密钥、访问令牌及模型私有推理过程不作为验收材料收集。敏感证据通过受控位置引用，不能全部复制进可公开下载的报告。

P0 表示安全泄露、越权发布、数据破坏等必须立即停止的问题；P1 表示核心链路失败、严重内容错误漏入已批准产物、错误答案映射等阻断验收的问题。P2／P3 可在明确不影响核心正确性和安全的前提下形成已知限制；不得把答案错误降级为界面瑕疵。

### 28.3 附件使用与证据目录

`acceptance/README.md` 为入口。阶段定义在 `mvp-plan.yaml`；最小与完整用例分别在 `minimum-cases.yaml`、`full-cases.yaml`；`capability-matrix.template.yaml` 登记范围；`acceptance-report.template.md`、`evidence-manifest.template.json`、`delivery-checklist.md` 用于执行与签收。`demo-runbook.md` 提供现场演示顺序。

```text
acceptance-runs/<run-id>/
  environment.json      实际应用、Hermes、模型、规则与渲染版本
  results.json          用例结果及实际执行时间
  artifacts/            学生卷、教师卷、Word 与快照文件
  restricted/           受限输入、答案及检查证据，另设访问控制
  logs/                 脱敏事件、调用、成本及恢复记录
  report.md             统计、缺陷、范围与签收结论
  manifest.sha256       本次验收文件指纹
```

上面目录是未来执行时产生的证据，不在本次交付中伪造。报告中的 run_id、实际模型 ID、耗时、费用、通过率和签名默认留空。验收参数缺失或真实运行证据不全时，结论必须为 BLOCKED／NOT_RUN，而不是通过。

### 28.4 最终签收标准

“基础框架已交付”至少要求 M1 真实可复现；“最小 MVP 已完成”要求 G-MIN；“完整 MVP 可受控试用”要求 G-FULL。正式学校考试适用性、对外发布条件和推广范围还需按使用政策与当前能力审定，不能凭本地技术测试自动获得。

**签收人应能在不依赖原开发者手工补文件、改数据库或粘贴假结果的情况下，独立完成配置、真实生成、检查、编辑、审核、导出、恢复与问题追溯。达不到这一点，就仍属于设计材料或未完成工程。**
